# 掌中工具箱 Palm Toolbox

跨平台（iOS / Android）效率工具集 App。基于 **Expo + React Native + TypeScript** 开发，一套代码同时构建双端应用。

当前版本已实现 **房贷计算器（提前还款测算）**、**存款计算器（定期单利测算）**、**理财计算器（活期理财收益）**、**个税计算器（工资薪金累计预扣法）**、**汇率换算（Frankfurter 实时汇率）**、**单位换算（长度 / 重量）**、**记账本（支出 / 收入流水）**、**待办清单（快捷添加 + 完成统计）** 与 **金价查询（上海金 + 品牌挂牌价）**，9 个工具全部上线。

## 快速开始

```bash
# 安装依赖
npm install

# 启动开发服务器（ Expo Go 扫码预览，或按 a / i 打开模拟器）
npm start

# 类型检查
npm run typecheck

# 单元测试（房贷 + 存款 + 理财 + 个税 + 汇率缓存 + 单位换算 + 记账本 + 待办 + 金价 + 计算统计，共 153 个用例）
npm test
```

- **iOS**：`npm run ios`（需要 macOS + Xcode）
- **Android**：`npm run android`（需要 Android Studio + 模拟器）
- 无 Mac / 无模拟器时，可用手机安装 **Expo Go**，扫描终端二维码直接预览。

### 构建 Android 测试 APK

无需发布到应用市场。首次构建需要 Expo 账号并将项目关联到 EAS；构建在 EAS 云端执行，不要求本机安装 Android Studio：

```bash
npx eas-cli@latest login
npx eas-cli@latest init
npm run build:android:preview
```

构建完成后，从终端输出或 Expo 构建页面下载 APK，在 Android 手机上打开安装；也可以连接已开启 USB 调试的手机，用 `adb install <APK路径>` 安装。首次安装时，Android 可能会要求允许该来源安装应用。

## 房贷计算器说明

**计算模型**：等额本息

```
月供 M = P × r × (1+r)^n / [(1+r)^n − 1]     r = 年利率/12，n = 期数
```

**提前还款两种模式**：

| 模式 | 规则 | 适用场景 |
| --- | --- | --- |
| 减少月供 | 期限不变，按剩余本金重算月供 | 降低每月压力 |
| 缩短期限 | 月供不变，反解新的期数 | 节省利息最大化 |

**边界处理**：全额还清（无后续月供，节省全部剩余利息）、零利率、输入校验（金额必须为正且提前还款额 < 剩余本金）、末期尾差自动吸收、金额展示四舍五入到元。

**导出**：还款计划支持导出 CSV（期数 / 月供总额 / 月供本金 / 月供利息 / 剩余总额），通过系统分享面板发送。

## 存款计算器说明

**计算模型**：定期存款（整存整取）单利

```
利息 = 本金 × 年利率 × 存款年数 + 本金 × 日利率 × 零头天数
日利率 = 年利率 ÷ 360        零头天数 = 月 × 30 + 天
```

**到期日**：按开户日「对年对月对日」推算，月末不足时取当月最后一天（如 1 月 31 日存 1 个月 → 2 月 28/29 日）。到期日与计息天数（实际日历天数）随结果一同展示。

**交互**：本金、期限（年 / 月 / 天）、存款日期、利率改动即时重算，无需点击；「常用利率」提供常见挂牌利率预设，也可手动输入实际执行利率。存期内遇利率调整，仍按开户日利率执行。

## 理财计算器说明

**计算模型**：活期理财，单利、按日计息，支持两种常用口径

```
七日年化：收益 = 本金 × 七日年化收益率 ÷ 365 × 持有天数
万份收益：收益 = 本金 ÷ 10000 × 每万份收益 × 持有天数
参考日收益 = 总测算收益 ÷ 持有天数
```

**交互**：「七日年化 / 万份收益」分段切换，聚焦另一行输入时自动切换口径，未参与计算的一行淡化显示；「常用收益率」「常用万份收益」提供参考值预设，持有天数可从 7 天到 730 天快速选择或自定义（上限 3650 天）。结果实时更新，展示总测算收益、本息合计与参考日收益。

**边界处理**：收益率上限 30%、万份收益上限 100 元；本金 / 天数缺失或天数非整数时给出提示；收益与日收益均保留两位小数，日收益由未取整的总收益折算，避免二次舍入。

## 个税计算器说明

**计算模型**：工资薪金所得预扣预缴，累计预扣法

```
累计应纳税所得额 = 累计收入 − 5,000 × 月份数 − 累计五险一金 − 累计专项附加扣除
本月应扣税 = 累计应纳税所得额 × 预扣率 − 速算扣除数 − 累计已扣税
到手工资 = 月薪 − 五险一金 − 本月应扣税
```

**预扣率表**（累计应纳税所得额）：3%（≤36,000）、10%（≤144,000，速算 2,520）、20%（≤300,000，16,920）、25%（≤420,000，31,920）、30%（≤660,000，52,920）、35%（≤960,000，85,920）、45%（>960,000，181,920）。

**页面流程**：输入页填写月薪、五险一金个人部分、专项附加扣除后点击「开始计算」，进入「年度扣税明细」页：累计收入 / 累计扣税总额 / 税后到手总额 / 月均扣税四张汇总卡，加实际税负、全年应纳税所得额，以及 12 个月逐月扣税与到手工资表（含合计行），支持 CSV 导出。

**边界处理**：累计应扣税额小于已扣税额时本期按 0 计（差额留待年度汇算清缴）；月薪为 0 或扣除项超过月薪时不产生负数税额；税额按月四舍五入到分，累计值由逐月税额累加，保证表格自洽。

## 汇率换算说明

**数据源**：Frankfurter（欧洲央行 ECB 参考汇率），接口 `https://api.frankfurter.dev/v1/latest?from=CNY`。`api.frankfurter.app` 现已 301 跳转至 `.dev/v1`，代码直接使用新域名，少一次跳转。

**缓存策略**（Web 端为 `localStorage('fx_rates')`，React Native 使用 AsyncStorage 同名 key）：

| 场景 | 行为 |
| --- | --- |
| 缓存 ≤ 1 小时 | 直接使用缓存，不发起请求 |
| 缓存已过期 | 请求接口，成功后写入缓存 |
| 请求失败 + 有缓存 | 使用上次缓存，提示「汇率可能过期」 |
| 请求失败 + 无缓存 | 提示获取失败，可手动重试 |

**换算模型**：以 1 CNY 为基准一次取回全部币种，任意两种货币按交叉汇率换算

```
1 FROM = rates[TO] ÷ rates[FROM] TO
换算结果 = 金额 × 交叉汇率
```

**交互**：金额支持两位小数与千分位；源 / 目标币种可从 30 种 ECB 币种中选择，也可点「常用币种」快速切换；中间圆形按钮一键互换；结果卡展示换算金额、目标币种与正反向参考汇率；常用货币 chips 可直接切换目标币种；右上角刷新按钮强制跳过缓存。

**边界处理**：请求 10 秒超时；非 2xx、网络异常或汇率数据为空时抛错并回退缓存；选择币种与另一侧相同时自动互换，避免 FROM = TO。

## 单位换算说明

**支持范围**：长度 / 重量两类，统一换算到基准单位（长度 cm、重量 g）后再换算到目标单位。

| 分类 | 单位 |
| --- | --- |
| 长度（8） | 厘米 cm / 英寸 in / 英尺 ft / 码 yd / 尺（市尺）/ 千米 km / 海里 nmi / 英里 mi |
| 重量（5） | 克 g / 盎司 oz / 磅 lb / 克拉 ct / 斤（市斤） |

**换算系数（精确定义值）**

| 单位 | 系数 | 单位 | 系数 |
| --- | --- | --- | --- |
| 1 英寸 | 2.54 厘米 | 1 盎司 | 28.349523125 克 |
| 1 英尺 | 30.48 厘米 | 1 磅 | 453.59237 克 |
| 1 码 | 91.44 厘米 | 1 克拉 | 0.2 克 |
| 1 尺（市尺） | 1/3 米 ≈ 33.3333 厘米 | 1 斤（市斤） | 500 克 |
| 1 海里 | 1.852 千米 |  |  |
| 1 英里 | 1.609344 千米 |  |  |

**常用换算组合**（结果卡下方列表，点击即切换该组合）

- 长度：厘米和英寸、厘米和尺、厘米和码、厘米和英尺、海里和千米、英里和千米
- 重量：盎司和克、磅和克、克拉和克、斤和克

**交互**：输入即时换算，支持 4 位小数；两个单位之间圆形按钮一键互换；结果卡展示换算值、目标单位与正反向单位换算率；切换分类自动回到该分类默认组合（长度 cm → in，重量 oz → g）。

**精度**：结果 ≥1000 保留 2 位、≥1 保留 4 位、<1 保留 6 位，并去掉末尾 0（如 0.393701、2.54、1,852）。

## 记账本说明

**三视图单页结构**：进入记账本后底部 Tab 在「记一笔 / 明细 / 统计」之间切换，不跳转页面，状态与月份保持连贯。

| 视图 | 内容 |
| --- | --- |
| 记一笔 | 支出 / 收入分段切换、大字号金额输入、最近 3 笔金额快速填入、6 类分类网格、记账日期、备注 |
| 明细 | 月份切换、当月支出 / 收入 / 结余汇总、全部 / 支出 / 收入筛选、按日分组 + 当日小计、单条左滑编辑删除 |
| 统计 | 本月结余（含较上月支出涨跌）、支出 / 收入分类占比进度条、近 6 个月收支双柱趋势（点柱切月） |

**数据模型**

```ts
{ id, type: 'expense' | 'income', amount, category, categoryIcon, date: 'YYYY-MM-DD', time: 'HH:mm', note, createdAt }
```

**分类**：支出——餐饮 / 交通 / 购物 / 娱乐 / 医疗 / 其他；收入——工资 / 奖金 / 理财 / 兼职 / 红包 / 其他。

**存储**：AsyncStorage key `ledger_records`（对应 Web 端 `localStorage('ledger_records')`），整表覆盖写入；读取时逐条校验并归一化，损坏数据自动丢弃而不影响其余记录。

**校验与边界**：单笔金额 > 0 且 ≤ 999,999.99；未填金额保存时 Toast 提示；日期可选 2000–2050 年；月份不能切到未来，可无限回溯历史。

**导出**：明细页底部「导出本月流水（CSV）」把当月记录（日期,时间,类型,分类,金额,备注，按时间升序）通过系统分享面板发出，可存到文件 App、备忘录或邮件。

**统计口径**：按记账日期归属月份；分类占比按金额降序，百分比 = 该分类金额 ÷ 当月同类型合计；结余 = 当月收入 − 当月支出。

## 待办清单说明

**三页流程**：列表主页（筛选 + 快捷添加）→ 详情页（精确编辑）→ 统计页。

| 页面 | 内容 |
| --- | --- |
| 列表主页 | 全部 / 今天 / 重要 / 已完成 四个 Tab（带计数）、按时间远近分组（已过期 / 今天 / 明天 / 本周内 / 以后）、卡片勾选完成、左滑编辑删除、长按多选批量处理、下拉刷新 |
| 详情页 | 内容（60 字）、日期（今天 / 明天 / 后天 / 本周日 / 自定义）、提醒时间（预设 + 自定义 5 分钟步进）、优先级三档、分类标签、删除 |
| 统计页 | 本周完成 / 连续打卡 / 总计完成 / 待处理四张卡、本周每日完成柱状图、已完成分类分布、过期提醒 |

**数据模型**

```ts
{ id, content, date: 'YYYY-MM-DD', time: 'HH:mm' | '',
  priority: 'high' | 'medium' | 'low',
  category: 'work' | 'life' | 'study' | 'shopping' | null,
  completed, completedAt: number | null, createdAt }
```

**快捷添加的智能识别**：输入一句话回车即创建，自动抽取并保留剩余文字作为内容。

| 输入示例 | 识别结果 |
| --- | --- |
| `明天下午3点开会` | 内容「开会」· 明天 · 15:00 |
| `周五 17:00 写周报` | 内容「写周报」· 本周五 · 17:00 |
| `下周一 提交方案` | 内容「提交方案」· 下周一 |
| `10月25日 陪家人` / `2026-11-11 09:30 抢购` | 指定日期（可带时间） |
| `重要 交电费` / `!! 交房租` / `随意 看看书` | 优先级 重要 / 重要 / 随意 |
| `晚上8点半 追剧` | 内容「追剧」· 20:30 |

支持的关键词：今天 / 明天 / 后天 / 大后天、周X / 星期X / 礼拜X（含「下周」「下下周」）、X月X日、YYYY-MM-DD、上午 / 下午 / 中午 / 晚上 / 凌晨 + X点（X点半）、HH:mm。

**排序与分组**：未完成按「日期 → 时间（未设时间靠后）→ 优先级 → 创建时间」排序；已完成按完成时间倒序，并分成今天完成 / 昨天完成 / 更早完成。

**完成与统计**：勾选后写入 `completedAt`，卡片划线并移入「已完成」；本周指自然周（周一至周日）；连续打卡从今天（今天无完成记录则从昨天）向前数连续有完成记录的天数。

**存储**：AsyncStorage key `todo_list`（对应 Web 端 `localStorage('todo_list')`），读取时逐条校验归一化，损坏数据自动丢弃。

## 金价查询说明

**数据源**：`https://tmini.net/api/gold-price`（免费公开接口，无需 key，`Access-Control-Allow-Origin: *`），一次请求同时返回上金所现货品种、品牌金店挂牌价与银行投资金条。

| 区块 | 内容 |
| --- | --- |
| 上海金 Au99.99 | 主力卡展示最新价（元/克）、涨跌额与涨跌幅、今开 / 最高 / 最低 |
| 品牌挂牌价 | 12 家品牌（周大福、老凤祥、周生生、老庙、中国黄金、菜百、六福、潮宏基、谢瑞麟、周六福、周大生、金大福），每行标注相对基础金价的溢价，可按品牌 / 价格切换排序 |
| 银行金条 | 20 家银行投资金条报价，按价格升序，默认展示 5 家可展开 |
| 其他行情 | 黄金 T+D、伦敦金、白银、铂金、钯金 |

**解析口径**

- 现货取 `metals` 中的 `黄金_9999`（缺失时退化为「今日金价」），统一展示为 `Au99.99`；
- `stores` 里混着国际品种（伦敦金 / 纽约黄金）、大盘基准价（今日金价 / 黄金价格）、投资金条（投资类）与水贝批发价，按关键词黑名单剔除，只留真实品牌金店；
- 品牌全称统一转简称（老庙黄金 → 老庙、菜百首饰 → 菜百、六福珠宝 → 六福）；
- 溢价 = 品牌挂牌价 − 上海金最新价；涨跌额 = 最新价 − 今开（不是相对昨收），页面标注「较今开」；
- 涨红跌绿（国内行情惯例）。

**缓存策略**：`gold_quote`，TTL 5 分钟；打开页面先读缓存，过期才请求；请求失败回退上次缓存并提示「金价可能过期」，无缓存时提示获取失败并可重试。接口限流 10 次/分钟，缓存足以规避。

**免责**：品牌牌价不含工费，实际成交以门店为准；数据仅供参考，不构成投资建议。

## 我的：计算次数与夜间模式

### 计算次数

「我的」页顶部的计算次数卡展示 **累计 / 今天 / 近 7 天**，点进去是完整的计算记录页。

**什么算一次计算**，两种工具类型分开统计，避免虚增：

| 工具类型 | 计入时机 |
| --- | --- |
| 按钮型（房贷、个税） | 每点一次「开始计算」记一次 |
| 实时型（存款、理财、汇率、单位） | 改动过参数后**离开页面**记一次；只打开看看不算 |

**存储**：AsyncStorage key `calc_stats`，结构为 `{ total, tools: { [kind]: { count, lastAt, lastSummary } }, days: { 'YYYY-MM-DD': n } }`，`days` 只保留最近 120 天。写入做了 400ms 防抖，连续操作不会频繁落盘；读取时逐字段校验，脏数据自动丢弃。

**计算记录页**包含：

- 累计次数大数字 + 今日 / 近 7 天 / 用过的工具数
- 近 7 天柱状图（今天高亮），右上角显示与上周同期的环比
- 按工具看列表：次数降序，显示最近使用时间与参数摘要（如「本金 ¥100000 · 1年0月0日 · 1.55%」），点击直达该工具
- 一键清空（二次确认）

### 夜间模式

主题分三层：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 调色板 | `src/theme/theme.ts` | `colors`（浅色）/ `darkColors`（深色）两套同构调色板，键名完全一致 |
| 上下文 | `src/theme/ThemeContext.tsx` | `mode: light / dark / system`、`useThemeColors()`、`useThemedStyles()`，偏好存 AsyncStorage key `theme_mode` |
| 消费 | 各页面 | `const colors = useThemeColors(); const styles = useThemedStyles(makeStyles);` |

**为什么样式表要写成 `(colors) => StyleSheet.create(...)`**：RN 的样式对象在模块加载时就固化了颜色值，只有把样式表变成按调色板重新生成的函数，切换主题时才能整体换色。所有页面统一了这个写法。

**历史硬编码色**：早期页面在局部手写了 `#F7F9F8`、`#2C3A36` 这类颜色，深色模式下由 `useThemedStyles` 按 `DARK_REMAP` 映射表统一改写（约 90 条），不必逐个文件返工。

**范围**：默认「跟随系统」，也可在「我的 → 外观」里固定为浅色或深色；开关状态即时生效并持久化。`app.json` 的 `userInterfaceStyle` 已改为 `automatic`。

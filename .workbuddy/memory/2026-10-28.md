- 结论：**走 GitHub Releases**，APK 不入 git 历史。理由：单文件 79.8 MB 逼近 GitHub 100 MB 硬限制，且 git 历史永久保留（仓库 `.git` 现在仅 3.9 MB，一旦提交就变 ~84 MB，后续每版再叠 80 MB 且无法清除）。

## APK 瘦身（80 MB → 约 25 MB）

- 先量体积再动手：解析 79.8 MB 的 APK，`lib/` 占 **72.3 MB（91%）**，且 4 个 ABI 各存一份——x86 20.35 / x86_64 19.66 / arm64-v8a 19.03 / armeabi-v7a 13.28；其余 `classes*.dex` 2.44、`assets/index.android.bundle` 2.00、`res/` 0.99、other 1.31。
- `.so` 与 JS bundle 在包内都是 **STORED（未压缩、页对齐）**，所以不要指望 deflate；`useLegacyPackaging: true` 能压小但破坏 16 KB 页对齐，不采用。
- 关键判断：**ABI / R8 都是 Gradle 属性，不归 eas.json 管**，要用 `expo-build-properties` 写进 `app.json` 的 plugins。`eas.json` 无需改动（`preview` 已有的 `distribution: internal` + `buildType: apk` 就是 release 变体，R8 才生效；若改成 `developmentClient: true` 就变 debug，失效）。
- 落地：`npx expo install expo-build-properties`（~58.0.11）+ app.json plugins `android.buildArchs: ["arm64-v8a"]`、`enableMinifyInReleaseBuilds: true`。
- 字段名以 SDK 58 文档 + 插件源码为准：`buildArchs` → gradle `reactNativeArchitectures`；`enableMinifyInReleaseBuilds` → `android.enableMinifyInReleaseBuilds`（`enableProguardInReleaseBuilds` 是旧名，插件里有 `fixupDeprecated…` 兼容）；资源收缩叫 `enableShrinkResourcesInReleaseBuilds`（必须与 minify 同开）。
- 体积预估（按实测压缩后大小相加）：arm64 单架构 = 19.03 + 6.78 ≈ **25.8 MB**；再加 armeabi-v7a ≈ **39 MB**；`enableBundleCompression` 实测 bundle 2.00 → 0.88 MB，可再省 1.12 MB（代价启动略慢）。
- 顺手修掉 doctor 报的配置问题：SDK 58 的 `@expo/config-types` 已无 `newArchEnabled`，从 app.json 删除（纯无效字段，无行为影响）。`expo-doctor` 现在 19/20，只剩 expo 58.0.12→58.0.20 等 3 个 patch 版本落后（历史遗留，未动）。
- 校验：`expo config --type prebuild` 插件配置解析正确、tsc 通过、测试 153/153。
- 待办（用户侧）：重新构建后用新包替换 Release；`versionCode` 建议 +1（app.json 未显式设置，默认 1）；README 下载表里的体积 / SHA-256 需同步更新。

## SHA-256 与发版检查清单

- 用户重新构建成功，包体积 **26.09 MB**（预估 25.8 MB，吻合）；随即问 SHA-256 怎么来的、要不要改。
- 结论：**必须改**。SHA-256 是对整个文件逐字节做的摘要，构建时间戳、签名块、zipalign 填充变一点值就全变，每个新包都要重新算；对不上等于告诉用户「文件被换过」。
- 新增 `scripts/apk-hash.mjs` + npm script `apk:hash`（`npm run apk:hash -- <apk路径>`，node crypto 流式，跨平台，输出体积 + SHA-256）。已用旧包验证：输出 `913f5425…0125e13e` 与 README 原值完全一致。
- README：下载表「文件大小」改为约 26 MB；SHA-256 格改为占位 `（发布前用 npm run apk:hash 生成后填入）`（旧值已不适用于新包，宁可留占位也不留错值）；新增「发布到 GitHub Releases 的检查清单」小节（算哈希 → 填表 → versionCode 递增），并补全各平台校验命令（PowerShell `Get-FileHash`、`certutil -hashfile`、`shasum -a 256`、`sha256sum`）。
- app.json 显式加 `android.versionCode: 1`（与当前包一致），以后每版递增。
- 校验：`expo config --type prebuild` 正常、doctor 19/20、tsc 通过、测试 153/153。
